컨테이너 생명주기 관리와 대화형 모드의 상관관계 이해
문제 상황:
상황: 개발 환경 구축을 위해 docker run -it ubuntu bash 명령어로 컨테이너에 접속하여 각종 패키지를 설치하고 환경 설정을 진행함.
현상: 작업 완료 후 컨테이너 내부에서 exit 명령어를 입력하여 터미널을 빠져나오자, 실행 중이던 컨테이너가 즉시 Exited 상태로 변하며 중지됨. 
다시 접속하기 위해 매번 start와 attach를 반복해야 하는 번거로움이 발생함.

원인 가설:
컨테이너에 들어갔다가 나가면 원래 컨테이너도 종료되는 것일 수 있다.
이를 보안하는 방법이 있을 것이다.


확인:
(docker ps -a 확인): exit 직후 컨테이너 상태를 확인한 결과, Exited 상태임을 확인.
(exec 테스트): 이미 실행 중인 다른 컨테이너(Nginx 등)에 docker exec -it로 접속한 뒤 exit을 시도함.
이 경우 컨테이너가 죽지 않고 계속 돌아가는 것을 확인.
ctrl p + q를 했을 때에도 죽지 않고 계속 돌아가는 것을 확인.

해결:
백그라운드 실행: 컨테이너를 처음 띄울 때 -d (detached) 옵션을 사용하여 백그라운드에서 영구적으로 돌아가게 설정함. 
접속: 이미 돌아가고 있는 컨테이너에 docker exec -it my-dev bash로 접속함.
결과: 이제 exec로 들어간 터미널에서 exit을 해도, 메인 프로세스가 살아있으므로 컨테이너는 중지되지 않음.

배운점:
도커 컨테이너는 하나의 가상머신이 아니라 하나의 프로세스 묶음이다라는 핵심 원리를 실무적인 트러블슈팅을 통해 이해함.
실행 방식(run)과 관리 방식(exec)에 따라 컨테이너의 생존에 어떤 영향을 주는지 명확히 구분할 수 있게 됨.
향후 워크스테이션 구축 시, 서비스 중단 없는 환경 설정을 위해 run -d와 exec 조합을 기본 전략으로 채택하기로 함.
